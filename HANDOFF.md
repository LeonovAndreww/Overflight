## 1. Что это за проект

**Overflight** — клиентский мод для Minecraft. Он добавляет в небо самолёты на
реальных высотах и их инверсионные следы (автор зовёт их «химтрейлы»: в России так
называют любые следы, без теории заговора). Мод только визуальный, игровой
механики в нём нет.

Исходная задумка автора (4.09.2026):
- самолёты летают на реальных эшелонах;
- следы появляются и живут по реальной физике: влажность, температура, тип двигателя
  (критерий Шмидта–Апплмана);
- мод работает с любыми шейдерами и с Voxy / Distant Horizons;
- он детерминирован: у всех игроков на сервере одинаковые самолёты, без пакетов, только
  по сиду мира и игровому времени;
- есть API и команды для админов: вызвать свой рейс, «горящий», «дымящий», конвой, очистить
  небо. Аирдропы и обломки делают сами админы, мы даём им основу и события.

Главная ценность для автора — **визуальный реализм**. Он хочет сидеть в доме в
майнкрафте, смотреть на небо и видеть, как пролетают самолёты, как следы расползаются,
меняют форму и постепенно исчезают. Он сам фотографирует небо и сравнивает с ним.

## 2. Устройство репозитория

```
overflight-core/      чистая Java без Minecraft: физика, трафик, следы, геометрия. Тесты здесь.
  atmo/               ISA, Schmidt–Appleman, HumidityField (поле влажности), Illumination
  traffic/            TrafficGenerator (детерминированный трафик по ячейкам/слотам), каталог самолётов, ManualTraffic
  trail/              TrailSampler (выборка следа по сетке времени эмиссии), Scattering, SkyCover
  render/             SkyProjection (проекция на «оболочку» неба + кривизна Земли),
                      TrailMeshBuilder (ленты), TrailPuffBuilder (спрайты: клубы, полосы падения, спирали),
                      AircraftMeshBuilder, MeshBuffer
  config/             OverflightConfig (пресеты), ConfigIo
backends/fabric-26.2/ ОСНОВНОЙ бэкенд. Его исходники синхронизируются в остальные (Sync-задача в build.gradle)
backends/fabric-26.1/ свои: SkyPipeline, SkyDraw, mixin/SkyRendererMixin
backends/fabric-26.3/ свои: SkyPipeline, Compat, SkyDraw, mixin/SkyRendererMixin, шейдеры (renderpearl API)
backends/fabric-1.21.11/ свои: Compat, SkyRenderHooks, SkyPipeline, SkyDraw, mixin, contrail.vsh (Loom remap)
common/resources/     текстуры (trail.png — атлас из трёх стадий, puff.png — 7 ячеек спрайтов), mixins.json
tools/                генераторы текстур и RenderPreview — программный растеризатор настоящего кода мода
```

Ключевые идеи:
- Вся геометрия лежит на «оболочке неба» вокруг камеры. Направления точные, параллакс
  сохраняется, есть тест.
- Следы рисуются **в фазе неба**: миксин на `SkyRenderer.renderSunMoonAndStars` TAIL, сразу
  после солнца и луны. Поэтому облака (ванильные, шейдерные, Voxy) рисуются поверх.
  - Настройка `graphics.drawInSky`.
  - Если хук неба не вызвался в этом кадре, мод возвращается к старой отрисовке вместе с
    полупрозрачной геометрией мира. Проверка покадровая.
- Под Iris программу для следов в фазе неба можно выбрать: `ShaderPacks.SkyProgram`.
  - `plain` — по умолчанию, ванильный шейдер.
  - `sky` — SKY_TEXTURED пака.
  - `textured` — TEXTURED пака.
  - Iris выбирает программу при сборке пайплайна, поэтому для каждого варианта есть свой
    пайплайн.
- Цвет следа берётся из атрибутов окружения игры: `SUNRISE_SUNSET_COLOR`, `SKY_COLOR`,
  `SKY_LIGHT_COLOR` (`Illumination.tintFromSky`).
- `graphics.detailedTrails` включает спрайты. Это «тяжёлый» режим, без него остаются только
  ленты (облегчённый режим, о котором просил автор).

### Известные баги и сомнительные места
- Без шейдеров ночная подкраска может уходить в синий/фиолетовый: окружение берётся из
  `SKY_LIGHT_COLOR`.
- `clearSky` (затухание следов под водой и в лаве) сглаживается **за кадр**, а не по
  времени, поэтому скорость зависит от FPS.
- При слепоте и тьме (blindness/darkness) следы не прячутся.
- В 26.2 `SkyDraw` создаёт `GpuBuffer` на каждый вызов: три в кадр, освобождаются с
  задержкой в 12 вызовов. Можно перейти на кольцевой буфер.
- Сборка спрайтов на насыщенном небе (55 следов, preset fancy, traffic busy): примерно
  4,1 мс/кадр плюс 1,2 мс на ленты (замер `RenderPreview -Dscene=sky -Dbench=1`). Дорого.
- `DevAutoShot` лежит в релизном jar. Он срабатывает только при наличии файла
  `overflight-autoshot` в каталоге игры, но вообще-то это dev-код.

## 4. Сборка и тесты на Linux

На ноутбуке была Windows, Temurin 25. Нужно:

```bash
# На сервере (leonov-hp) JDK лежат в ~/jdks/jdk21 и ~/jdks/jdk25 (Temurin, tarball с
# api.adoptium.net: apt-репозиторий Adoptium там виснет). ~/.gradle/gradle.properties уже
# настроен. Gradle 9.5.1 распакован в ~/gradle-9.5.1: ./gradlew не может скачать
# дистрибутив (Java-SSL получает handshake error от services.gradle.org), поэтому:
#   JAVA_HOME=~/jdks/jdk25 nice ~/gradle-9.5.1/bin/gradle build --no-daemon
# Первая конфигурация со скачиванием Loom/Minecraft занимает ~45 минут (сеть и Immich рядом).
./gradlew build --no-daemon -Porg.gradle.java.installations.paths=/usr/lib/jvm/temurin-21-jdk-amd64,/usr/lib/jvm/temurin-25-jdk-amd64
./gradlew :overflight-core:test
```
- Gradle 9.5.1 (wrapper скачается сам). Нужен интернет: maven.fabricmc.net, Maven Central.
- Память: на сервере 6.7 ГБ, рядом Immich. В `~/.gradle/gradle.properties` поставить
  `org.gradle.jvmargs=-Xmx2g` и `org.gradle.workers.max=2`. Параллелить сильнее не надо.
- CI (`.github/workflows/build.yml`) собирает на ubuntu с JDK 21+25. Это рабочий рецепт.

## 6. Требования пользователя

Самый важный раздел. Собран по всей переписке с 4.09 по 17.10.2026. Автор не всегда
может объяснить, как надо, но очень точно видит, как не надо.

### 6.1 Внешний вид следов — главное

**Реализм прежде всего, без компромиссов.**
- «Мне не нужен компромисс… у самолёта какое крыло важнее — правое или левое?»
- Красиво и реалистично должно быть одновременно.
- «Изучи и сделай как надо и как красиво».
- Если решение выглядит хуже реальности, оно не годится, как бы научно ни было обосновано.

Что автор **критиковал** (не повторять):
- **Серые следы без шейдеров.** Это была долгая эпопея. След должен быть белым относительно
  неба, а не темнее его. Автор мерил пипеткой: след `90a1bf`, небо `adcbff` — «буквально
  тёмно-серый».
- **Слишком яркие и «светящиеся» следы**: неоновые полосы, светятся ночью как маяк. Белый
  `ffffff` при облаках `a4b2d0`–`c3d1ef` — «слишком ярко». Нужна не яркость, а
  правдоподобие.
- **Полосы «зебры»** — поперечные полосы прозрачности, которые ещё и ползут.
- **Пунктир и «бусы» вдоль следа.** Пунктир нужно убирать «грамотно», а не маскировать.
- **«Цепь»**: след, пустой внутри, у которого видно только границы.
- **Мерцание**, дёрганье, «голова следа прыгает» вперёд-назад, линия «ползёт как парабола».
- **Белые поперечные полосы** на распадающихся следах — швы текстур.
- **«Осьминоги»** на конце хвоста — «хуйня и убого выглядит».
- **«Гирлянда»** — линия с кругами снизу вместо спирали.
- **«Палки в небе»**: просто прямые белые линии разной ширины, параллельные линии.
- **Резкое начало и конец следа**: старый широкий след, начинающийся из ниоткуда; обрыв хвоста.
- **Внезапное исчезновение** следа целиком, в один кадр.
- **Пропадание следов ночью.** Ночь в майнкрафте не чёрная, и в жизни следы ночью видно
  (луна, подсветка солнцем из-за горизонта).
- **Оранжево-красные следы на закате**, когда солнце ещё не коснулось горизонта, и скачки
  цвета: белый → красный → белый за 800 тиков.
- **Зёрна и точки**, когда весь след состоит из них, а также серость после добавления
  гранул.
- **Следы видны под водой.**
- **Следы просвечивают сквозь непрозрачные облака** шейдерпака и сквозь чанки Voxy.
- Почти прозрачный след не должен «вырезать» облако перед собой.
- След не должен заметно отставать от самолёта (была дыра в 3,2 длины самолёта).
- **Однообразие**: все следы стареют одинаково, спирали одинаковые.

Что автор **хочет видеть** (по его фото и словам):
- Короткоживущие следы **веретенообразные**: у самолёта как «воздух от пули», потом
  расширяются, достигают пика, растворяются и к концу сужаются. Хвост плавно растворяется
  или сливается из двух полос в одну.
- Долгоживущие следы **неравномерно расползаются**: одна сторона разваливается вширь, как
  облако, другая остаётся стройной линией. Ветер сдувает их вбок, перекашивает местами.
- **Параллельные пряди** бывают; иногда одна остаётся, а соседнюю сдувает.
- **Перистость** — это не прозрачность, а то, что след **распадается на мелкие части**.
  Текстура «воздушная», края рваные, не «сияние».
- **Разрывы и остатки**: висящие в небе «палки» без самолёта, остатки следа.
- **Неравномерная плотность** по длине.
- **Лёгкая дуга**: следы чуть огибают шар Земли (сделано: `SkyProjection`, кривизна).
- **Спираль («штопор», «пружинка»)** на уже сильно рассеянном следе. Она неровная: витки
  смещаются группами, поворачиваются, у конца следа между витками больше места, разного
  размера. Автор выбрал «нижние два» варианта толщины (толще).
- **Освещение как у неба**: след не только серый или белый, свет солнца ложится на него
  с учётом закатного цвета. Сделано через атрибуты окружения, но под Complementary это ещё
  не подтверждено.
- **Ночью** следы видны слабо, подсвечены луной. Высокие следы после заката ещё горят
  солнцем.
- Огни самолётов не должны быть огромными и сливаться в один. Автор помнит мигание
  «красный, зелёный, миг белого», но просил **не менять**.

### 6.2 Производительность и настройки
- Если детализация реально бьёт по FPS (больше погрешности), нужна **настройка графики**.
  Облегчённая «legacy» версия должна оставаться: это `graphics.detailedTrails`.
- Мод настраивается через Mod Menu, пресет выбирается там же.
- Пресеты **разделены по смыслу**:
  - `preset` (realistic / fancy / chemtrail / custom) — как выглядит и как быстро стареет небо;
  - `traffic.preset` (modern / busy / quiet / coldwar / …) — кто летает и сколько.

  Автора злило, когда настройки трафика попадали в визуальный пресет.
- **Fancy**: больше видимых следов, живут не слишком мало. «Ждать 40 минут — это жестяк»
  для декорации, но и голое небо плохо. Решено через `SkyCover`: старые следы гаснут,
  когда покрытие неба превышает долю.
- У каждого пресета должно быть **короткое текстовое описание**, что конкретно меняется, а
  не только таблица цифр. Автора бесит выбирать пресет «не зная, что теряешь».

### 6.4 Процесс, git, тексты — что запрещено и что важно
- **Коммиты**: короткие conventional-сообщения `feat:` / `fix:` / `build:` / `refactor:` /
  `docs:`. `test:` только в редких случаях (тест после бага или реально важный). Тело —
  коротко, по делу и **что сделано**.

  **Без «книг»**, без претенциозного, «излишне человеческого» тона, сленга, «как школьник
  писал». Не смешивать несвязанные изменения в одном коммите.
- Авторство: автор — коммиттер, Claude — соавтор через `Co-Authored-By` (так в его
  репозитории QR Checker).
- **Не переписывать историю без спроса**: автор ругался за переименование «Initial commit».
  Force-push — только с явного разрешения.
- **Не пушить, не тегать, не публиковать без указания.** Версию не поднимать раньше времени:
  «зачем пушить 0.3.0 вообще? запушишь когда отладим по реальным фото».
- Названия релизов — **без «глав книги»** («First flight» звучит «иишно»). Просто номер
  версии.
- README и описания — «человеческие, не иишные», аккуратные, не претенциозные. **Не тащить
  внутреннюю кухню разработки** (вроде объяснения «72×») в README, комментарии к коду,
  описания и коммиты. Не писать в описании мода о чужих проблемах (Voxy/Iris/Vulkan).
- **Не врать и не фантазировать.** Автор ловил на «репозиторий приватный» (неправда) и на «я
  вернул как было» (не вернул). Если что-то не проверено — так и сказать.
- **Не трогать мышь и клавиатуру** (computer-use): это выжигает его лимиты.
- **Беречь токены**: «не уничтожь токены, пожалуйста». Не делать лишних дорогих действий.
- Перед каждым визуальным изменением сравнивать с его фото (`external/photos/`) и
  проверять своими глазами на скриншотах. Автор не любит, когда ему выдают непроверенное.
- Показывать варианты для сравнения — хорошая практика: он выбирал толщину спиралей из
  нескольких.
- **Отладочные команды для сравнения вариантов за один заход** автор одобряет: «разве
  нельзя командой отладочной все версии за один заход попробовать?».
